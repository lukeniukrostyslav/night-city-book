# NIGHT CITY BOOK — MASTER PROMPT

Ты работаешь над оригинальным коммерческим романом «ГОРОД, КОТОРЫЙ ПОЯВЛЯЕТСЯ НОЧЬЮ».

Перед любой новой работой:
1. Прочитай PROJECT_STATE.md.
2. Прочитай ARCHITECTURE.md, если он существует.
3. Прочитай CHARACTER_BIBLE.md, WORLD_RULES.md, MYSTERY_LEDGER.md и CHAPTER_STATUS.md.
4. Проверь последние написанные главы и их состояние.
5. Не выдумывай отсутствующие решения как утверждённые.
6. Если архитектура изменилась, сначала обнови соответствующий документ, затем текст.

## Художественный принцип
Читатель должен чувствовать, что живёт вместе с героями, а не изучает загадку.

Каждая сцена должна по возможности иметь:
- конкретное место;
- присутствующих персонажей;
- цель;
- препятствие;
- действие;
- реакцию;
- изменение состояния;
- новую информацию или эмоциональный сдвиг;
- сенсорные детали;
- причину читать дальше.

## Баланс книги
Не допускать доминирования одной механики. Чередовать:
- семья и дом;
- друзья;
- обычная жизнь;
- юмор;
- путешествие;
- исследование;
- тайна;
- опасность;
- конфликт;
- эмоциональные последствия;
- возвращение домой;
- новые отношения.

## Персонажи
У каждого важного персонажа должны быть собственные желания, страхи, решения и последствия. Не использовать персонажей как декорацию для Лео.

## Тайна
- Не раскрывать раньше времени.
- Не менять правила задним числом.
- Не делать героев глупыми ради сохранения тайны.
- Каждая крупная разгадка должна быть подготовлена ранее.
- Вести MYSTERY_LEDGER.

## Стиль
Живой, кинематографичный, эмоциональный, сенсорный, с юмором из характера персонажей. Показывать действия и реакции вместо сухого пересказа. Не копировать стиль конкретного живого или современного автора.

## Объём
Ориентир романа: 85 000–95 000 слов. Не растягивать текст искусственно. Точные диапазоны глав утверждаются в ARCHITECTURE.md.

## Производственный порядок
Концепция → архитектура → персонажи → мир → правила → карта тайн → план сцен → главы → редактура → финальная проверка.

После каждой завершённой главы:
- посчитать точное число слов;
- обновить CHAPTER_STATUS.md;
- обновить PROJECT_STATE.md при необходимости;
- сохранить изменения отдельным GitHub commit;
- записать SHA коммита;
- проверить, что файл действительно сохранён.

## Проценты
Использовать только фактический прогресс. 100% означает, что соответствующий блок полностью выполнен и сохранён/проверен в GitHub.
